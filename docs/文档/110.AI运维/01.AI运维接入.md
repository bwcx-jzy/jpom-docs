Jpom 提供可移植的 AI 运维 Skill（`jpom-ops`）：通过现有 REST API + 长期 token 完成工作空间、节点、项目、构建、脚本、资产、监控、分发、系统与日志的查询，并支持**显式授权后**的受控写操作。MCP Server 规划中。

::: warning 安全提示
- 长期 token（请求头 `JPOM-USER-TOKEN`）只放本地环境变量或 `chmod 600` 的本地文件，**不要提交到仓库或截图传播**。
- 默认**只读**。写操作（触发构建、启停项目、杀进程、在线升级）必须同时满足 `JPOM_OPS_ALLOW_WRITE=true` 与 `--confirm`，执行前须回显环境/对象并获明确同意。
- 请按**工作空间最小权限**创建 token，并在正确环境（开发/测试/生产）操作；Jpom 操作日志可用于审计。
:::

## 支持方式

| 方式 | 状态 | 适用工具 |
|---|---|---|
| `jpom-ops` Skill（指令 + REST 脚本） | 可用（REST 全能力，只读默认） | DeepSeek Harness、Claude、Cursor、其他可加载指令/执行脚本的 Agent |
| MCP Server（独立 sidecar） | 规划中 | Claude Desktop、Cursor、VS Code MCP 客户端等 |

Skill 不修改 Jpom 主程序，仅调用 Jpom REST API（已在 2.11.13 逐条验证，兼容 2.11.x）。

## 快速开始

Skill 脚本为**跨平台**实现：`scripts/jpom_api.py`（Python 3.8+，仅标准库）；Linux/macOS 可直接用薄包装 `scripts/jpom-api.sh`。

**Linux / macOS**

```bash
export JPOM_BASE_URL=http://127.0.0.1:2122   # Jpom Server 地址
export JPOM_TOKEN_FILE=/path/to/jpom-token   # chmod 600；或使用 JPOM_TOKEN
export JPOM_WORKSPACE=DEFAULT

./scripts/jpom-api.sh capabilities           # 能力清单
./scripts/jpom-api.sh workspaces             # 校验 token
./scripts/jpom-api.sh nodes
./scripts/jpom-api.sh projects --node-id <节点ID>
./scripts/jpom-api.sh build-history
```

**Windows（cmd / PowerShell）**

```bat
set JPOM_BASE_URL=http://127.0.0.1:2122
set JPOM_TOKEN_FILE=C:\path\jpom-token
set JPOM_WORKSPACE=DEFAULT
python scripts\jpom_api.py capabilities
python scripts\jpom_api.py nodes --limit 5
```

然后在 AI 工具中加载 `SKILL.md`（并允许其执行上述命令），即可用自然语言查询与巡检。

## 能力覆盖（REST）

| 域 | 命令 |
|---|---|
| 工作空间 | `workspaces` `workspace-list` `workspace-env` |
| 节点 | `nodes` `node-groups` `node-machine-info` `node-monitor` `node-process` |
| 项目 | `projects` `project-info` |
| 构建 | `builds` `build-get` `build-history` `build-log` `build-groups` `repositories` `repository-groups` `branches` |
| 脚本 | `scripts` `scripts-all` `script-logs` `node-scripts` `node-script-logs` |
| 资产 | `machines` `ssh-assets` `ftp-assets` `docker-assets` |
| 监控/分发/系统 | `monitors` `dispatch` `dispatch-logs` `system-info` `check-version` `server-logs` `backups` `clusters` |
| 用户与审计 | `users` `permission-groups` `login-logs` `operate-logs` `recent-logs` `log-read` |

### 受控写操作（默认禁用）

| 命令 | 说明 |
|---|---|
| `build-start --id <buildId> [--branch-name x]` | 触发构建 |
| `build-cancel --id <buildId>` | 取消构建 |
| `build-rerelease --log-id <logId>` | 按历史记录重新发布 |
| `project-operate --node-id <nid> --id <pid> --opt start\|stop\|restart` | 项目启停重启 |
| `node-kill-pid --node-id <nid> --pid <pid>` | 结束节点进程 |
| `system-upgrade [--machine-id <id>]` | 在线升级（真实触发，最高风险） |

开启方式：`export JPOM_OPS_ALLOW_WRITE=true`，并在命令后加 `--confirm`。脚本会拒绝未授权或未确认的写操作（分别返回 `rc=3` / `rc=4`）。

::: tip 验证状态
以上写命令已在 Jpom 2.11.13 开发环境真实执行验证：触发构建成功（status=2）、取消长任务（status=7）、按历史重建、项目启停重启（真实 PID 变化）、结束指定进程。`system-upgrade` 仅验证安全闸门，**未真实触发升级**，请谨慎使用。
:::

### 不在范围（请使用 Web UI）

终端（SSH / Docker CLI / 节点控制台）、脚本在线执行、文件浏览与上传、用户/权限/系统配置写操作——属于 WebSocket 交互通道或高风险管理面，不适合交给 AI 自动执行。

## 各 AI 工具适配

- **DeepSeek Harness**：安装 `jpom-ops` 到 DSH 可发现的 skills 目录，配置 `JPOM_*` 环境变量。
- **Claude / Cursor**：MVP 阶段将 `SKILL.md` 作为项目指令/规则；MCP Server 发布后可使用 `adapters/claude-desktop/`、`adapters/cursor/` 的配置示例（`JPOM_READ_ONLY=true`）。
- **VS Code MCP 客户端**：MCP Server 发布后按 `adapters/vscode-mcp/` 配置。
- **注意**：`adapters/` 中的 `mcp*.json` 示例指向尚未发布的 `jpom-mcp-server`，仅作配置参考、**当前不可直接使用**；MVP 阶段请用 Skill 方式。

## 常见问题

- **`code=800`/鉴权失败**：token 无效或修改密码后失效，重新生成长期 token；可设 `JPOM_STRICT_CODE=1` 让脚本以非 0 退出。
- **`code=405` 对象不存在**：如构建 ID、记录 ID 不存在；先用列表命令取正确 ID。
- **`500 No corresponding resource found`**：接口路径与版本/部署（context-path）不匹配，按实际版本校正。
- **无数据/权限不足**：检查 `JPOM_WORKSPACE`、token 权限与分页参数。
- **连接失败**：检查 `JPOM_BASE_URL`、端口（默认 2122）、网络与代理。
