## 什么时候需要它

标准 Spring Boot Jar 直接用 **Jar 运行方式**最省事（Jpom 自带进程管理）。
下面这些情况才建议用 **Dsl 运行方式**自己写脚本：

- 需要自定义启动参数、启动前做检查（端口占用、目录准备）
- 一个项目要起多个实例，或要按环境切 profile
- 需要自定义「假死」判定（HTTP 探活而不是只看进程）
- 需要 reload（改配置后热重载）

## 先说 JDK 版本（最容易踩坑）

Jpom 插件端本身要求 **JDK 8+**，但你脚本里启动的业务项目用哪个 JDK 由脚本决定。
不同 JDK 对 JVM 参数的接受度差别很大，**照抄老教程的参数在 JDK 9+ 上会直接启动失败**。

| 参数 | JDK 8 | JDK 9 ~ 13 | JDK 14+ | 建议 |
| --- | --- | --- | --- | --- |
| `-XX:PermSize` / `-XX:MaxPermSize` | 可用（已废弃，有警告） | **不支持**，报 `Unrecognized VM option` | **不支持** | 改 `-XX:MetaspaceSize` / `-XX:MaxMetaspaceSize` |
| `-XX:+UseConcMarkSweepGC` 及 CMS 系列（`+CMSClassUnloadingEnabled`、`+CMSPermGenSweepingEnabled`） | 可用 | 可用但已废弃 | **已移除**（14 起） | 用 G1（9+ 默认）：`-XX:+UseG1GC` |
| `-Djava.ext.dirs=...` | 可用 | **已移除**（9 起不再支持） | 已移除 | 用 `-cp` 指定 classpath，或 `--module-path` |
| `-XX:MaxNewSize` | 可用 | 可用 | 可用 | 一般交给堆参数控制即可 |

::: danger 最常见的报错长这样
```text
Unrecognized VM option 'PermSize=32M'
Error: Could not create the Java Virtual Machine.
```

看到这个就说明：脚本里的 JVM 参数和你实际用的 JDK 版本不匹配。
:::

按版本直接可用的参数模板：

```bash
# JDK 8
JVM="-server -Xms512m -Xmx512m -XX:MetaspaceSize=128m -XX:MaxMetaspaceSize=256m -Dfile.encoding=UTF-8"

# JDK 11 / 17 / 21（G1 是默认 GC，这里显式写出来便于排查）
JVM="-server -Xms512m -Xmx512m -XX:MetaspaceSize=128m -XX:MaxMetaspaceSize=256m -XX:+UseG1GC -Dfile.encoding=UTF-8"
```

::: tip Spring Boot 版本也要注意
Spring Boot **3.2 起**，可执行 Jar 的启动类包名从 `org.springframework.boot.loader.JarLauncher`
调整为 `org.springframework.boot.loader.launch.JarLauncher`。
脚本里如果写死了 MainClass，升级 Spring Boot 后可能报 `ClassNotFoundException`。
**用 `java -jar` 启动就没有这个问题**，推荐优先用 `-jar`。
:::

## Linux 脚本

完整脚本（放到项目目录，命名 `project.sh`）：

```bash
#!/bin/bash
# 用项目 ID 做进程唯一标识，避免同机多实例互相干扰
TAG="jpom-app-${PROJECT_ID}"
LIB="${PROJECT_PATH}"
JAR="${LIB}/app.jar"
LOG="${LIB}/run.log"
# JDK 8 / 11+ 通用：Metaspace 参数两者都支持
JVM="-server -Xms512m -Xmx512m -XX:MetaspaceSize=128m -XX:MaxMetaspaceSize=256m -Dfile.encoding=UTF-8"

status_pid() {
  # -Dapp.tag 会出现在命令行里，用它精确定位本项目的进程
  pgrep -f -- "-Dapp.tag=$TAG" | head -1
}

start() {
  if [ ! -f "$JAR" ]; then
    echo "jar not found: $JAR"
    exit 1
  fi
  nohup java $JVM -Dapp.tag="$TAG" -jar "$JAR" --spring.profiles.active=prod >> "$LOG" 2>&1 &
  sleep 2
  tail -n 10 "$LOG"
}

stop() {
  pid=$(status_pid)
  if [ -z "$pid" ]; then
    echo "not running"
    return
  fi
  echo "stopping $pid"
  kill "$pid"
  # 最多等 10 秒，不退就强杀
  for i in $(seq 1 10); do
    [ -z "$(status_pid)" ] && break
    sleep 1
  done
  pid=$(status_pid)
  [ -n "$pid" ] && kill -9 "$pid"
}

status() {
  pid=$(status_pid)
  if [ -n "$pid" ]; then
    echo "running:$pid"
  else
    echo "stopped"
  fi
}

case "$1" in
  start)   start  ;;
  stop)    stop   ;;
  restart) stop; start ;;
  status)  status ;;
  *) echo "usage: $0 {start|stop|restart|status}"; exit 1 ;;
esac
```

配套的 DSL：

```yaml
description: Java 应用（DSL 托管）
run:
  start:
    scriptId: project.sh
    scriptArgs: start
  status:
    scriptId: project.sh
    scriptArgs: status
  stop:
    scriptId: project.sh
    scriptArgs: stop
  restart:
    scriptId: project.sh
    scriptArgs: restart
  execPath: ./            # 让脚本在项目目录执行，相对路径才符合直觉
```

::: tip 为什么不直接用 jps
`jps` 只能看到「是个 java 进程」，区分不了是哪个项目。
用 `-Dapp.tag=${PROJECT_ID}` + `pgrep -f` 才能精确匹配；同机多实例、多环境时尤其重要。
:::

## Windows 脚本

同名 `project.bat`，用 `jps -v` 匹配标识后 `taskkill`：

```bat
@echo off
set TAG=jpom-app-%PROJECT_ID%
set LIB=%PROJECT_PATH%
set JAR=%LIB%\app.jar
set LOG=%LIB%\run.log
set JVM=-server -Xms512m -Xmx512m -XX:MetaspaceSize=128m -XX:MaxMetaspaceSize=256m

if "%1"=="start" goto start
if "%1"=="stop" goto stop
if "%1"=="status" goto status
exit /b 1

:start
if "%JAVA_HOME%"=="" (
  echo please configure JAVA_HOME
  exit /b 2
)
start "" javaw %JVM% -Dapp.tag=%TAG% -jar %JAR% >> %LOG% 2>&1
exit /b 0

:stop
for /f "tokens=1" %%i in ('jps -v ^| findstr "%TAG%"') do taskkill /F /PID %%i
exit /b 0

:status
for /f "tokens=1" %%i in ('jps -v ^| findstr "%TAG%"') do @echo running:%%i
exit /b 0
```

::: warning Windows 上的注意事项
- 用 `javaw`（无控制台）而不是 `java`，否则会弹黑框
- 脚本文件是 `.bat` 时，`scriptId` 要写 `project.bat`
- `taskkill /F` 是强杀；需要优雅停机可改用 `curl` 调 actuator 的 shutdown 端点
:::
