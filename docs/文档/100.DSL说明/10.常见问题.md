## 先看这张表

| 现象 | 最可能的原因 | 去哪看 |
| --- | --- | --- |
| 保存报「没有配置 run.status」 | YAML 里没写 `run.status` | 本文第 1 节 |
| 保存报 YAML 解析错误 | 用了 Tab 缩进、冒号后少空格 | 本文第 1 节 |
| 点启动报「脚本模版不存在」 | `scriptId` 拼错 / 脚本没同步到节点 | 本文第 2 节 |
| 点启动报「项目目录没有任何文件」 | 项目目录是空的 | 本文第 2 节 |
| 启动后状态一直「未运行」 | `status` 没输出 `running:<PID>` | 本文第 3 节 |
| 进程已死但显示「运行中」 | `pgrep` 匹配到了别的进程 | 本文第 4 节 |
| 业务日志文件找不到 | 相对路径 + 没配 `execPath` | 本文第 5 节 |
| 停止/重启总是超时 | 应用停得慢，等待时间太短 | 本文第 6 节 |
| 中文乱码 | 日志/控制台编码不匹配 | 本文第 7 节 |
| 手动能跑，Jpom 跑不起来 | 环境变量、工作目录、权限不同 | 本文第 8 节 |

::: tip 排查三件套
1. **项目控制台**：【节点&项目】->【项目列表】-> 行内【控制台】，能看到每次 start/stop/status 的输出和退出码
2. **项目日志文件**：路径就是脚本里的 `$PROJECT_LOG_FILE`（默认 `{插件端data}/project-log/{项目ID}/{项目ID}.log`）
3. **节点脚本执行记录**：【脚本管理】->【脚本执行记录】，手动执行脚本时看这里的输出
:::

## 1. 保存就失败

### 报「没有配置 run.status」

DSL 项目保存时会强制校验 `run.status` 是否存在，因为 Jpom 要靠它轮询状态。补上即可：

```yaml
run:
  status:
    scriptId: project.sh
    scriptArgs: status
```

### 报 YAML 解析错误

| 常见错误 | 正确写法 |
| --- | --- |
| 用 Tab 缩进 | 全部改成 **2 个空格** |
| `start:` 后面直接换行又顶格写 `scriptId` | `scriptId` 要比 `start` 多缩进 |
| `scriptArgs:start` 冒号后没空格 | `scriptArgs: start` |
| 值里有冒号没加引号（如时间 `12:00`） | 加引号 `"12:00"` |

小技巧：在表单的 **配置示例** 选项卡里先粘一份官方模板，再逐段改，比自己从零写稳。

## 2. 启动阶段直接报错

### 「脚本模版不存在」/「缺少脚本」

`scriptId` 有三种来源，按顺序匹配，任何一步对不上就报这个错：

| 你写的 scriptId | 实际去找的地方 | 怎么修 |
| --- | --- | --- |
| `project.sh` | 项目目录下的同名文件 | 用【文件】确认文件确实在项目目录里；注意大小写 |
| 一串 32 位 ID 或脚本名 | 该逻辑节点上的节点脚本 | 【脚本管理】->【节点脚本列表】确认脚本已下发，必要时点【同步缓存】 |
| `G@xxxx` | 脚本库脚本，`xxxx` 是标记 | 【系统管理】->【资产管理】->【脚本库】确认标记，并已同步到节点 |

::: warning 最容易忽略的一点
在【脚本列表】里建了脚本，但没**分发到当前节点**，DSL 就找不到它。节点脚本列表里能看到「节点名称」这一列，确认脚本出现在目标节点下。
:::

### 「项目目录没有任何文件,请先到项目文件管理中上传文件」

启动前 Jpom 会检查项目目录。空目录直接拦下：先用【文件】上传，或让构建发布一次产物。

### 脚本没有执行权限

Linux 下脚本被 `bash xxx.sh` 方式执行一般不受影响；如果你在脚本首行写了 `#!/usr/bin/env bash` 又想直接执行，记得 `chmod +x`。

## 3. 启动了但状态一直「未运行」

这是最常见的现象，按顺序排查这三步：

**第一步：status 脚本到底输出了什么**

在服务器上手动跑一遍（把参数换成你的）：

```bash
cd /path/to/项目目录
bash project.sh status
echo "exit=$?"
```

**第二步：最后一行是不是 `running:<数字>`**

Jpom 只认这一行的格式：

```text
running:12345          # 正确
running:12345:8080     # 正确，带端口
running                # 错误：没有 PID，判定为未运行
is running             # 错误：不是以 running: 开头
```

**第三步：PID 是不是真实存活**

```bash
ps -p 12345 -o pid,cmd
```

::: tip 还有一个隐藏原因：脚本被当成自己匹配了
如果 status 里用 `ps -ef | grep xxx` 而不排除 grep 自身，可能匹配到 `grep xxx` 这个进程，输出一个已经退出的 PID。
推荐用 `pgrep -f xxx | head -1`，或 `ps -ef | grep -v grep | grep xxx`。
:::

## 4. 进程已死但显示「运行中」

反过来，状态判断也会误报，常见两个原因：

1. **匹配规则太宽**：`pgrep -f java` 会把机器上所有 java 进程都算进来 → 一定要带项目唯一标识（通常用 `${PROJECT_ID}` 拼一个 `-Dapp=${PROJECT_ID}` 或 tag）
2. **僵尸进程**：父进程没回收，PID 仍在。用 `ps -o stat= -p <pid>` 看到 `Z` 就是僵尸，重启父进程或 `kill -9`

## 5. 业务日志文件找不到

当 DSL 项目跑起来后，你项目里 logback / log4j 生成的日志文件找不到，大概率是**相对路径**问题：

- 不配 `execPath` 时，脚本在**脚本文件所在目录**执行，不是项目目录
- 日志框架里写 `./logs/app.log`，就会落到那个目录下

两种改法（任选）：

| 改法 | 做法 |
| --- | --- |
| 改 YAML | 加 `run.execPath: ./`，让脚本在项目目录执行 |
| 改日志配置 | 把日志输出路径改成绝对路径 |

::: tip 顺带说明
DSL 项目的**控制台日志**（Jpom 抓的 stdout）和业务日志（logback 写的文件）是两份东西，别混淆。控制台日志路径见 `$PROJECT_LOG_FILE`。
:::

## 6. 停止 / 重启总是超时

Jpom 停项目后会轮询状态直到「未运行」，默认只等约 5 秒（10 次 × 500 毫秒）。
如果应用优雅停机需要更久，会看到「停止超时」但进程其实还在收尾。

改**插件端** `conf/application.yml`（改完重启插件端）：

```yaml
jpom:
  project:
    # 等待次数
    status-wait-time: 10
    # 每次间隔，单位毫秒
    status-detection-interval: 500
```

也可以先确认 stop 脚本本身是不是真的能停：

```bash
bash project.sh stop
sleep 2
bash project.sh status
```

## 7. 中文乱码

| 位置 | 配置 |
| --- | --- |
| 控制台输出编码 | 插件端 `jpom.system.console-charset` |
| 系统日志编码 | 插件端 `jpom.system.log-charset` |
| 项目日志文件编码 | 项目详情【日志编码格式】，或插件端 `jpom.project.log.file-charset` |

Windows 下默认是 GBK，跨平台脚本建议在脚本里显式 `export LANG=en_US.UTF-8`（或按需设 GBK）。

## 8. 手动能跑，Jpom 跑不起来

差异通常出在这几处，按顺序比一遍：

| 差异点 | 手动执行 | Jpom 执行 | 怎么对齐 |
| --- | --- | --- | --- |
| 工作目录 | 你在哪 `cd` 就在哪 | 脚本文件目录或 `execPath` | 脚本里写绝对路径 |
| 环境变量 | 登录 shell 已加载 `~/.bashrc` | 不加载 | 用 `scriptEnv` 或【环境变量】显式配 |
| 用户 | 你登录的用户 | **插件端进程的用户** | 检查该用户对目录/文件的权限 |
| PATH | 完整 PATH | 精简 PATH | 脚本里用绝对路径调用 java / node |

## 9. 一个可以直接用的自检脚本

把这段放到项目目录执行，能一次性看出「脚本在哪、用什么用户、状态输出对不对」：

```bash
#!/bin/bash
echo "== 当前用户: $(id -un)"
echo "== 当前目录: $(pwd)"
echo "== PROJECT_ID=${PROJECT_ID:-未设置}"
echo "== PROJECT_PATH=${PROJECT_PATH:-未设置}"
echo "== 脚本位置: $(readlink -f "$0")"
echo "== status 输出:"
bash "$0" status | tail -3
```

在项目【控制台】里点一次【启动】/【停止】，把这里的输出和手动执行的结果对照，差异点基本就是问题所在。
