## 这个页面能帮你做什么

当一个项目的上线不再只是「拉一次代码、打一个包、发一台机器」，而是**多个仓库 + 多个步骤 + 多个发布目标**时，
用流水线把这条链路固定下来：一次运行按顺序跑完所有阶段，每一步的结果、日志、耗时都留痕。

流水线与「在线构建」并存、互不影响：老构建继续用，新链路用流水线。

## 和在线构建的区别

| 维度 | 在线构建 | 流水线 |
| --- | --- | --- |
| 仓库 | 一个构建任务一个仓库 | 一条流水线可挂**多个仓库源**，各自挂到不同子目录 |
| 步骤 | 一段构建脚本 + 发布配置 | **多个阶段**：构建 / 命令 / 发布 / 人工审批 / 通知，可排序、可禁用、可单独设失败策略 |
| 产物 | 构建产物目录 | 每个阶段可产出产物，发布阶段可按「来源阶段」取产物 |
| 取消 | 取消构建 | 取消运行：先受理、执行体退出后落「已取消」，界面区分「取消中」与「已取消」 |
| 数据 | BUILD_INFO | 独立表 `PIPELINE_INFO` / 运行记录，**不读写在线构建的数据** |

## 操作路径

| 步骤 | 菜单 |
| --- | --- |
| 1. 准备仓库 | 【在线构建】->【仓库信息】（流水线复用这里的仓库记录） |
| 2. 建流水线 | 【流水线】->【流水线列表】->【新增】 |
| 3. 跑一次 | 列表行内【运行】；运行中可【取消】 |
| 4. 看结果 | 行内【运行记录】-> 阶段结果 / 日志 / 下载日志 |

> 权限：流水线有独立权限点「流水线」（查看 / 编辑 / 执行 / 删除 / 下载日志），按权限组勾选即可；
> 列表与运行记录都按**工作空间**隔离，接口侧强制校验归属。

## 一、仓库源

一条流水线可以有多个仓库源，每个源指定：

| 字段 | 说明 |
| --- | --- |
| 源标识 | 阶段里用它作工作目录，例如 `backend` |
| 仓库 | 从仓库信息里选（GIT/SVN 均可） |
| 引用 | `branch:名称` 或 `tag:名称`，留空按仓库默认分支；界面上可直接选分支/标签 |
| 挂载目录 | 相对本次运行工作区的子目录；**留空时等于源标识**，必须唯一，不允许 `..`、`/` 开头或反斜杠 |
| 克隆深度 | 可选，深层历史很大的仓库建议填 1 |

每次运行都会新建独立工作区（`data/pipeline/workspace/<流水线>/<运行编号>/`），不同运行之间互不覆盖。

## 二、阶段

阶段可拖动排序，逐个启用/禁用；每个阶段可单独设置「失败即停」：

| 阶段类型 | 作用 | 主要配置 |
| --- | --- | --- |
| 构建 | 在某个仓库源目录里执行命令并产出产物 | 仓库源、工作目录、命令、产物目录 |
| 命令 | 执行检查/测试类命令，不产出产物 | 仓库源、工作目录、命令 |
| 发布 | 把一个阶段的产物发布到多个目标（跨发布方式） | 来源阶段、目标列表（项目 / SSH 项目 / SSH / FTP / Docker / **文件中心** 等）、发布前/后命令、失败即停 |
| 人工审批 | 等到审批通过再继续，超时判失败 | 超时时间、说明 |
| 通知 | 把本次运行结果发到脚本通知/Webhook | 通知事件、通知目标（脚本） |

> 工作目录只允许填「工作区根」或「某个仓库源目录（含其子目录）」，写别的路径保存时就会提示，
> 避免运行时指向一个不存在的目录。

### 发布到文件中心

发布目标选「文件中心」后，本阶段产物会存进【系统管理 -> 文件中心】，之后可被分发任务复用、也可直接下载：

| 配置 | 说明 |
| --- | --- |
| 保留天数 | 留空表示长期保留；填 N 表示 N 天后由文件中心按保留策略清理 |
| 别名码 | 用于在文件中心按标识检索这份产物，留空按流水线 ID 处理 |

同一个产物（内容完全相同的 MD5）重复发布不会产生重复文件，日志会写明「已存在」，按发布成功处理。

## 三、事件通知（钩子）

「事件通知」区解决的是「流水线状态变化时，怎么自动通知/联动其它系统」，与在线构建的「构建事件」用法一致：
**按事件选一条服务端脚本**，脚本在服务端同步执行；也可以配 **Webhook** 回调外部系统。

可用事件（运行级 + 阶段级共 10 个）：

| 事件 | 触发时机 |
| --- | --- |
| `run_start` | 运行开始（拉代码之前） |
| `run_success` / `run_failed` / `run_cancelled` | 本次运行的终态 |
| `run_finished` | 运行结束（终态之后总会触发，适合做汇总推送） |
| `stage_start` | 某个阶段开始执行 |
| `stage_success` / `stage_failed` / `stage_skipped` / `stage_cancelled` | 某个阶段的结果（跳过、取消也会通知，不会静默） |

**事件脚本**

- 脚本在服务端同步执行，**输出实时写进本次运行的日志**（带 `[事件 run_success]` 前缀），退出码也写在日志里；
- 脚本输出的执行记录会出现在【脚本管理 -> 服务端脚本 -> 执行记录】，触发方式为「构建事件」；
- 可用环境变量：`PIPELINE_ID`、`PIPELINE_NAME`、`PIPELINE_RUN`（运行编号）、`PIPELINE_RUN_ID`、`PIPELINE_EVENT`、
  `PIPELINE_STATUS`、`PIPELINE_STAGE_ID`、`PIPELINE_STAGE_NAME`，以及构建阶段注入的 `PIPELINE_SOURCE_*_DIR/COMMIT`、
  `PIPELINE_STAGE_*_ARTIFACT`；
- 脚本失败**不会改变本次运行结果**（通知是旁路能力），但失败原因会写进运行日志与【运行记录 -> 事件】。

**Webhook**

- 一个地址一次配置，可配多条（不同事件发不同系统）；支持 `GET` / `POST`，POST 支持 `form` 与 `json`；
- 可加请求头（每行一个 `KEY: VALUE`，例如 `X-Token: xxx`）；连接超时 5 秒、读取超时 10 秒，失败自动重试 1 次；
- 参数里带 `event`/`type`（事件码）、`pipelineId`、`pipelineName`、`runNumber`、`runId`、`status`、`stageId` 等，
  另外同名字段的大写形式（`PIPELINE_*`）也在，方便脚本化消费；
- 投递结果写在运行日志，并可在【运行记录 -> 事件】里看到每条地址的成功/失败与原因。

## 四、运行与取消

- 【运行】后返回运行记录，本次运行的状态、阶段结果、日志在【运行记录】里看；运行中日志每 2 秒增量刷新，长日志按页继续拉。
- 同一条流水线**同时只允许一个运行**：运行中再点【运行】会提示「正在运行」，避免两次运行抢同一个取消登记与状态。
- 【取消】的三种结果都会明确提示：
  - 已受理取消：等执行体退出后标记「已取消」；
  - 已在取消中：重复点击不会重复下发；
  - 没有找到执行体：本次运行按异常关闭处理（不会假装取消成功）。
- 服务重启后，未正常结束的运行会被标记为异常关闭，不会一直显示「运行中」。
- 【取消】会终止当前阶段正在跑的进程（含构建/命令/发布命令/通知脚本/事件脚本），并在**进程树确认退出后**才标记「已取消」；
  杀不掉时如实标记「异常关闭（附残留进程提示）」，不会假装取消成功。

## 五、常见问题

**发布阶段报「发布的文件或者文件夹为空」**：检查「来源阶段」是否填对；不填时默认取最近一个**非空**产物目录。

**同一发布目标被别的流水线占用**：发布目标按工作空间校验，跨空间的资产/项目不能作为目标。

**通知没收到**：通知阶段失败不会让流水线失败（它是告警通道，不是发布依据），失败原因写在阶段消息里。

**要不要开开关**：不需要，流水线是常规功能，菜单【流水线】直接可用；不想用就忽略，不影响原有构建。
