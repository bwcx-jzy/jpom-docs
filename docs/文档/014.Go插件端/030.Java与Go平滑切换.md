# Java 插件端与 Go 插件端平滑切换

> 适用场景：已在使用 Java 插件端，希望切换到 Go 插件端；或切换后需要回切 Java 插件端。
> 核心结论：两者使用**同一份配置**与**同一个数据目录**，切换 = 停一个、启动另一个；数据无需迁移，可随时回切。

:::danger 操作前必须备份
切换会短暂中断插件端（Server 上节点显示离线属于正常现象），操作前请备份安装目录：

```bash
tar czf ~/jpom-agent-backup-$(date +%Y%m%d-%H%M).tgz -C /opt/jpom/agent conf data bin lib 2>/dev/null
```
:::

## 1. 前置检查

- [ ] 已备份安装目录（至少包含 `conf/`、`data/`）；
- [ ] 记录当前 `data/INSTALL.json` 的 `installId` 与 Server 上机器资产的账号/端口；
- [ ] 确认 Server 节点当前在线，且没有正在执行的项目/脚本任务；
- [ ] Go 插件端安装包已下载并校验（见「安装与部署」）。

## 2. 推荐：先并行验证，再切换（不动生产）

在正式切换前，可以先用一套**独立目录 + 独立端口**的 Go 插件端验证功能：

1. 复制一份目录：

```bash
cp -r /opt/jpom/agent /opt/jpom/agent-go-test
cd /opt/jpom/agent-go-test
# 改端口，避免和生产的 Java 插件端冲突
sed -i 's/^  port: 2123/  port: 2124/' conf/application.yml
# 删除 INSTALL.json，让测试实例生成独立 installId，避免与生产节点身份冲突
rm -f data/INSTALL.json
```

2. 放入 Go 二进制与服务脚本后启动：`bin/AgentGo.sh start`；
3. 在 Server「机器资产」用同一套账号、端口 2124 新增机器，分配到一个测试工作空间生成节点；
4. 用 Server UI 对新节点做冒烟：监控、项目列表、文件列表、脚本列表/执行、控制台日志、WebSocket 控制台；
5. 确认无异常后再执行第 3 节的正式切换。

:::warning 并行实例注意
并行实例与生产 Java 插件端**共享项目目录**时，不要同时对同一个项目做启停/文件写操作，避免相互影响。仅用于只读验证最安全。
:::

## 3. 正式切换（同目录、同端口 2123）

### 3.1 停止 Java 插件端

```bash
cd /opt/jpom/agent
bin/Agent.sh stop
# 如果注册为 systemd，用：sudo systemctl stop jpom-agent
```

确认端口已经释放（没有输出表示端口空闲）：

```bash
ss -ltnp | grep 2123
```

### 3.2 放入 Go 二进制（保留 Java 文件以便回滚）

```bash
cd /opt/jpom/agent
# 解压 Go 安装包到临时目录，然后拷贝可执行文件与服务脚本
unzip -o /tmp/agent-go-<version>-release-linux-amd64.zip -d /tmp/go-agent-pkg
cp /tmp/go-agent-pkg/bin/agent bin/agent
cp /tmp/go-agent-pkg/bin/AgentGo.sh bin/AgentGo.sh
chmod +x bin/agent bin/AgentGo.sh
# 注意：不要覆盖 bin/Agent.sh 和 lib/Agent-*.jar，回切时要用
ls -l bin/
```

### 3.3 启动 Go 插件端

```bash
bin/AgentGo.sh start
bin/AgentGo.sh status
tail -n 50 logs/stdout.log
```

### 3.4 确认 Server 端恢复

1. 打开节点列表，确认该节点恢复在线（插件端地址/端口/账号未变，Server 无需修改机器资产）；
2. 打开节点监控，确认 CPU/内存/磁盘/网卡/进程有数据；
3. 抽查项目列表、脚本列表、文件管理、控制台日志。

:::tip 数据完全兼容
`data/project.json`、`script.json`、`workspace_env_var.json`、`whitelistDirectory.json` 等文件 Go 插件端会原样读取，不会丢字段；写回时保持同样的 JSON 结构与类型（原子写，避免半个文件）。
:::

## 4. 切换后验收清单

- [ ] 节点在线，监控数据正常（CPU/内存/磁盘/网卡/进程）
- [ ] 项目：列表、新建/编辑、启动/停止/重启、状态与端口、控制台日志、日志备份/下载
- [ ] 项目文件：列表、上传（含大文件分片）、下载、新建/重命名/删除、读取/编辑、压缩
- [ ] 脚本：列表、新增/编辑、执行并查看实时日志、执行记录同步、脚本库
- [ ] DSL 项目：状态/启动/停止/重载
- [ ] WebSocket：控制台日志 tail + 启停、脚本执行日志、插件端系统日志
- [ ] 系统：插件端配置读取、白名单、工作空间环境变量、缓存、系统日志
- [ ] 数据检查（可选，需在插件端机器上有脚本）：

```bash
# Java 数据目录 vs Go 数据目录 结构/类型/格式比对（0 error 为通过）
bash go-agent/script/verify-switch-data.sh --mode diff \
  --before /opt/jpom/agent/data --after /opt/jpom/agent/data
```

> 同目录切换时 before/after 是同一路径，主要用于切换前对备份目录做一次基线快照，切换后与基线比较：
>
> ```bash
> # 切换前（Java 停止后）
> bash go-agent/script/verify-switch-data.sh --mode snapshot --data /opt/jpom/agent/data --out /tmp/switch-before.json
> # 切换后（Go 启动并访问过一轮页面之后）
> bash go-agent/script/verify-switch-data.sh --mode compare --data /opt/jpom/agent/data --baseline /tmp/switch-before.json
> ```

## 5. 回切 Java 插件端

```bash
cd /opt/jpom/agent
bin/AgentGo.sh stop
bin/Agent.sh start          # lib/Agent-<version>.jar 仍在，可直接启动
# 或：sudo systemctl start jpom-agent
```

确认节点在线、项目/脚本列表正常即可。若 Server 提示项目/脚本与节点不一致，使用 Server 的节点同步或「孤独数据修复」功能重新绑定，**不要手改数据库**。

:::warning installId 与节点身份
同目录切换不会改变 `data/INSTALL.json`（安装 ID 不变），Server 侧节点身份保持不变，通常无需重新绑定。若你在并行测试时删除过 INSTALL.json，请以生产目录中的文件为准。
:::

## 6. 切换常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 节点一直离线 | 端口未监听（`ss -ltnp\\|grep 2123`）、机器资产地址/端口填错、账号密码与 `agent_authorize.json` 不一致、防火墙拦截 |
| 项目列表/脚本列表为空 | `project.json`/`script.json` 里的 `nodeId` 与 Server 当前节点 ID 不一致（常见于重建节点）；用 Server 的节点同步/孤独数据修复重新绑定 |
| 项目启动报 `nohup: java: No such file or directory` | 插件端进程没有 java 环境；按「安装与部署」第 6 节配置 `JAVA_HOME`/`PATH`（systemd 需写进 service） |
| 切换后 Server 提示版本异常 | `/info` 的 `manifest.version` 来自 Go 二进制构建版本；确认使用的是正式发布包，不要手工改版本号 |
| 端口被占用 | 旧进程未退出（`ps -ef\\|grep -E 'agent\\|Agent-'\`）；停止旧进程或用其它端口先验证 |
| 数据文件异常 | 恢复第 1 节的备份；不要手工编辑 `data/*.json`（会造成 Java/Go 都无法解析） |
