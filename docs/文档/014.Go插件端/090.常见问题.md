# Go 插件端常见问题（FAQ）

> 适用：使用 Go 插件端时遇到的安装、接入、项目执行、日志、升级等问题。
> 通用问题（Server、用户权限、构建等）请查看「常见问题」栏目其它页面。

## 1. 安装与接入

### Q1：Go 插件端需要安装 JDK 吗？

Go 插件端**自身不需要** JDK（单二进制）。但如果要启动 **Java 项目**（java -jar、classpath 等），目标机器仍需安装 JDK，且**插件端进程**必须能找到 java 命令（`JAVA_HOME`/`PATH`，systemd 要写在 service 里）。

### Q2：插件端启动了，但 Server 上节点一直离线？

按顺序排查：

1. 端口是否监听：`ss -ltnp | grep 2123`（Windows：`netstat -ano | findstr 2123`）；
2. 本机访问：`curl http://127.0.0.1:2123/` 应返回 `Jpom-Agent,Can't access directly,Please configure it to JPOM server`；
3. Server 机器资产地址/端口是否正确、协议（http/https）是否匹配；
4. 账号密码是否与插件端一致（见 Q3）；
5. 防火墙/安全组是否放行端口；
6. 插件端日志 `logs/stdout.log` 是否有鉴权失败/端口占用等错误。

### Q3：自动生成的插件端密码在哪里看？

如果 `conf/application.yml` 中 `jpom.authorize.agent-pwd` 为空，首次启动会自动生成并保存到：

```text
<安装目录>/data/agent_authorize.json
```

```bash
cat /opt/jpom/agent/data/agent_authorize.json
```

把其中的 `agentName` / `agentPwd` 填到 Server 的机器资产即可。该文件权限为 600，**不要**提交到代码仓库、不要截图外发。

### Q4：可以同时安装 Java 插件端和 Go 插件端吗？

可以**安装/共存**（同一目录保留两套启动入口即可），但**不能同时运行并写同一份 data/**。

- 正式切换：停一个、启另一个（见「Java 与 Go 平滑切换」）；
- 并行验证：必须使用**独立目录 + 独立端口 + 独立数据副本**，并删除副本中的 `data/INSTALL.json`（避免与生产节点身份冲突）。

### Q5：Go 插件端的内存/CPU 占用怎么看？

与普通进程一致：

```bash
ps -o pid,rss,pcpu,etime,cmd -p $(bin/AgentGo.sh status 2>/dev/null | grep -o '[0-9]\+')
```

Go 插件端常驻内存通常明显低于 Java 插件端；但**项目监控/进程扫描**（如进程列表、磁盘信息）会短时占用 CPU，属正常现象。

## 2. 项目与脚本

### Q6：节点上线后项目列表/脚本列表是空的？

这是 **nodeId 不一致**导致的（常见于重建节点、换机器、并行实例误用生产数据）。处理：

1. 确认 `data/project.json` / `script.json` 中条目的 `nodeId` 与 Server 当前节点 ID 一致；
2. 使用 Server 的「节点同步」或「孤独数据修复」功能重新绑定；
3. **不要**手工修改数据库或 JSON 文件。

### Q7：启动项目报 `nohup: failed to run command 'java': No such file or directory`？

插件端进程环境里没有 java。处理：

- 手工启动：先 `export JAVA_HOME=/path/to/jdk`、`export PATH=$JAVA_HOME/bin:$PATH` 再启动；
- systemd：在 service 文件里配置 `Environment=JAVA_HOME=...`、`Environment=PATH=...`；
- Windows 服务：在系统/服务环境变量中配置；
- 验证方式：用**插件端运行用户**执行 `java -version` 能成功。

### Q8：脚本执行输出乱码/项目日志乱码？

按编码配置处理：

- 脚本/命令输出：`jpom.system.console-charset`（Windows 建议 `GBK`）；
- 项目控制台日志：`jpom.project.log.file-charset`（默认 Windows=GBK，其它=UTF-8）；
- 插件端系统日志：`jpom.system.log-charset`（默认 UTF-8）。

修改后重启插件端生效。

### Q9：上传较大的文件失败？

- 项目文件上传走**分片**（每片大小由 Server 决定，默认 1MB），网络不稳定时会重试；
- 如提示大小超限，检查插件端 `spring.servlet.multipart.max-file-size` / `max-request-size` 是否被改小；
- 上传目录/项目目录磁盘空间是否充足。

## 3. 日志与排查

### Q10：日志在哪里？

| 日志 | 路径 |
| --- | --- |
| 插件端启动/运行日志 | `<安装目录>/logs/stdout.log` |
| 插件端业务日志 | `<安装目录>/logs/`（按日期/大小滚动，页面「插件端日志」可查看） |
| 项目控制台日志 | `<安装目录>/project-log/<项目ID>/<项目ID>.log`（自定义了日志路径则以项目配置为准） |
| 脚本执行日志 | `<安装目录>/data/script/<脚本ID>/log/<执行ID>.log` |

### Q11：如何快速确认插件端版本？

```bash
/opt/jpom/agent/bin/agent -version
```

Server 节点列表/节点详情也会显示插件端版本（来自 `/info` 的 manifest）。

## 4. 升级

### Q12：在线升级提示“不支持 Java 插件端升级包”？

Go 插件端不能用 `Agent-<version>.jar` 升级，请使用 Go 升级容器包 `agent-go-<version>-upgrade.jar`（或包含 Go 可执行文件的 zip），详见「在线升级与回滚」。

### Q13：升级后节点没起来怎么办？

1. 查看 `logs/stdout.log` 的错误；
2. 确认 `bin/agent` 存在且可执行；
3. 按「在线升级与回滚」第 6 节从 `bin/oldJars/` 恢复上一个版本并启动；
4. 若使用 systemd/Docker，确认其重启策略与目录权限。

### Q14：Docker 里能在线升级吗？

只读文件系统/不可写目录下不能自升级。推荐用镜像版本升级（更新镜像 tag 后重启容器），或把插件端目录挂载为可写卷后再使用在线升级。

## 5. 兼容性

### Q15：与 Java 插件端切换后，Server 上需要重新配置节点吗？

同目录/同端口切换不需要：机器资产（地址、端口、账号密码）与节点数据都不变，Server 会自动恢复在线。若更换了目录/端口或删除了 `INSTALL.json`，则相当于一个新安装，需要重新创建机器资产/节点。

### Q16：监控页面里 javaVersion、totalMemory 等字段为空？

Go 插件端没有 JVM，这类 Java 专有字段会显示为空/0，属正常现象，不影响监控的 CPU/内存/磁盘/网卡等功能。

### Q17：为什么有些提示文案是英文？

插件端会按请求语言（Server 下发的 `Accept-Language`）返回提示；若 Server/浏览器为英文环境则显示英文。可在 `conf/application.yml` 中配置 `jpom.system.lang`（如 `zh-CN`）。
