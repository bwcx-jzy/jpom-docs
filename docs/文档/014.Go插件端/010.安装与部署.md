# Go 插件端安装与部署

> 适用版本：Go 插件端随对应 Jpom 版本发布（与 Java 插件端同版本号），作为**可选的插件端安装方式**；它与 Java 插件端兼容同一份配置、同一份数据与同一套协议，可随时回切 Java 插件端。
> 若你的版本下载页没有 Go 插件端包，请继续使用 Java 插件端，或参考「Java 与 Go 平滑切换」评估后再升级版本。
> 适用场景：希望使用**单二进制、无 JDK 依赖、低内存**的插件端，或计划从 Java 插件端切换到 Go 插件端。
> 前置条件：一台能访问 Jpom 服务端的 Linux / Windows / macOS 主机；端口默认 2123（可配置）。

## 1. 认识 Go 插件端

Jpom 插件端（Agent）负责在目标机器上执行项目启停、脚本、文件管理、监控等任务。Go 插件端是用 Go 重写的实现，与 Java 插件端**协议、配置、数据完全兼容**：

| 项 | 说明 |
| --- | --- |
| 运行形态 | 单个静态二进制（bin/agent），不需要安装 JDK/JRE |
| 配置文件 | 与 Java 插件端**同一份** conf/application.yml（键名、默认值一致） |
| 数据目录 | 与 Java 插件端**同一个** data/ 目录（project.json、script.json、agent_authorize.json 等 schema 一致） |
| 通信协议 | 与 Java 插件端完全一致（HTTP + WebSocket，端口默认 2123，Jpom-Agent-Authorize 鉴权） |
| 与 Java 版关系 | 可在同一目录共存、随时切换/回切，数据无需迁移（见「Java 与 Go 平滑切换」） |

:::tip 运行 Java 项目仍需要 JDK
Go 插件端自身不需要 JDK，但要启动 **Java 项目**（java -jar / classpath 等）时，目标机器仍需安装 JDK 并让插件端进程能找到 java 命令（参考本文「6. 配置 JAVA_HOME/PATH」）。
:::

## 2. 下载与校验

1. 打开 Jpom 下载中心（文档站「日志&下载」→ 下载中心），进入对应版本目录；
2. 下载与目标平台匹配的 Go 插件端安装包：

```text
agent-go-<version>-release-linux-amd64.zip
agent-go-<version>-release-linux-arm64.zip
agent-go-<version>-release-windows-amd64.zip
```

3. 下载同目录的 `.sha1` 校验文件并校验（防止下载损坏/被篡改）：

```bash
# Linux / macOS
sha1sum agent-go-<version>-release-linux-amd64.zip
cat agent-go-<version>-release-linux-amd64.zip.sha1

# Windows PowerShell
Get-FileHash .\agent-go-<version>-release-windows-amd64.zip -Algorithm SHA1
```

## 3. 解压与目录布局

把安装包解压到你要安装的目录（下文以 `/opt/jpom/agent` 为例）：

```bash
sudo mkdir -p /opt/jpom/agent
sudo unzip agent-go-<version>-release-linux-amd64.zip -d /opt/jpom/agent
# 若 zip 内还有一层目录，把内容移动到 /opt/jpom/agent 下即可
sudo chmod +x /opt/jpom/agent/bin/agent /opt/jpom/agent/bin/AgentGo.sh
```

解压后的目录结构（与 Java 插件端保持一致）：

```text
/opt/jpom/agent/
├── bin/
│   ├── agent               # Go 插件端可执行文件
│   ├── AgentGo.sh          # 服务脚本（start|stop|restart|status|upgrade）
│   └── agent.pid           # 运行时生成
├── conf/
│   └── application.yml     # 配置文件（与 Java 插件端同一份）
├── data/                   # 数据目录（自动初始化）
├── logs/                   # 运行日志（stdout.log）
├── project-log/            # 项目控制台日志（未自定义路径时）
└── tmp/                    # 临时目录
```

## 4. 启动、停止与状态

使用包内自带的服务脚本（与 Java 插件端的 Agent.sh 用法一致）：

```bash
cd /opt/jpom/agent

# 启动（后台运行，日志输出到 logs/stdout.log）
bin/AgentGo.sh start

# 查看状态（运行中会输出 pid）
bin/AgentGo.sh status

# 重启
bin/AgentGo.sh restart

# 停止
bin/AgentGo.sh stop
```

首次启动会自动生成：

| 文件 | 说明 |
| --- | --- |
| data/INSTALL.json | 本机安装 ID（**请勿删除**，删除后与 Server 的节点/机器绑定会失效） |
| data/agent_authorize.json | 当 conf 中未配置 `agent-pwd` 时自动生成的鉴权账号（权限 600，**请勿泄露**） |

:::warning 同一目录不要同时运行两个插件端
Java 插件端与 Go 插件端**不能同时**运行并写同一个 data/ 目录（会互相覆盖数据）。切换时必须先停旧进程，再启动另一个（详见「Java 与 Go 平滑切换」）。
:::

## 5. 注册为系统服务（推荐）

### 5.1 Linux（systemd）

```ini
# /etc/systemd/system/jpom-agent.service
[Unit]
Description=Jpom Agent
After=network.target

[Service]
Type=simple
User=jpom
WorkingDirectory=/opt/jpom/agent
# 运行 Java 项目需要 java 命令：按实际 JDK 路径设置
Environment=JAVA_HOME=/usr/lib/jvm/java-8-openjdk-amd64
Environment=PATH=/usr/lib/jvm/java-8-openjdk-amd64/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
ExecStart=/opt/jpom/agent/bin/agent -base /opt/jpom/agent
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now jpom-agent
sudo systemctl status jpom-agent
```

:::tip 用 systemd 托管时的升级
使用 systemd 托管后，Go 插件端自升级（在线升级）会重启进程；若希望升级后由 systemd 拉起，可设置 `Restart=always`。也可以继续用 `bin/AgentGo.sh` 手工启停（二选一，不要重复拉起同一个实例）。
:::

### 5.2 Windows

安装包内提供 `bin\AgentGo.bat`（与 Linux 的 AgentGo.sh 用法一致）：

```bat
cd C:\jpom\agent

REM 启动（后台运行，输出写入 logs\stdout.log）
bin\AgentGo.bat start

REM 查看状态 / 重启 / 停止
bin\AgentGo.bat status
bin\AgentGo.bat restart
bin\AgentGo.bat stop
```

注册为 Windows 服务（任选一种，注意**只保留一种托管方式**，不要同时用服务 + 手工启动重复拉起）：

**方式 A：nssm（推荐，简单稳定）**

```bat
REM 下载 nssm 后执行（路径按实际修改）
nssm install JpomAgent "C:\jpom\agent\bin\agent.exe" "-base" "C:\jpom\agent"
nssm set JpomAgent AppDirectory "C:\jpom\agent"
nssm set JpomAgent AppStdout "C:\jpom\agent\logs\stdout.log"
nssm set JpomAgent AppStderr "C:\jpom\agent\logs\stdout.log"
nssm set JpomAgent AppExit Default Restart
nssm start JpomAgent
```

**方式 B：Windows 自带 sc**

```bat
sc create JpomAgent binPath= "C:\jpom\agent\bin\agent.exe -base C:\jpom\agent" start= auto
sc description JpomAgent "Jpom Agent"
sc start JpomAgent
```

> 用 `sc` 注册时，`binPath=` 的引号与空格处理较严格；如启动失败优先改用 nssm。

**方式 C：计划任务（无服务权限时）**

```bat
schtasks /create /tn "JpomAgent" /tr "C:\jpom\agent\bin\agent.exe -base C:\jpom\agent" /sc onstart /ru SYSTEM /rl HIGHEST
schtasks /run /tn "JpomAgent"
```

:::warning Windows 下运行 Java 项目需要 JAVA_HOME/PATH
无论是手工启动还是注册为服务，都要保证**插件端进程**能找到 `java.exe`：在「系统属性 -> 环境变量」中配置 `JAVA_HOME`，并把 `%JAVA_HOME%\bin` 加入 `PATH`；用 nssm/sc 注册后需重启服务使环境变量生效。验证：用插件端运行用户执行 `java -version` 能输出版本。
:::
## 6. 配置 JAVA_HOME/PATH（运行 Java 项目必需）

Go 插件端自身不依赖 JDK，但它执行的项目命令依赖系统里的 java。请确保**插件端进程**的环境变量包含 java：

```bash
# 验证：以插件端运行用户执行
java -version
which java
```

- 用 `bin/AgentGo.sh` 手工启动：在启动前 `export JAVA_HOME=...`、`export PATH=$JAVA_HOME/bin:$PATH`（或写入 /etc/profile，并保证非登录 shell 也生效）；
- 用 systemd：在 service 文件里写 `Environment=...`（见 5.1）；
- 用 Windows 服务：在服务/系统环境变量中配置 `JAVA_HOME` 与 `PATH`。

## 7. 接入 Jpom 服务端

1. 在 Server 的「资产管理 → 机器资产」中新增机器：
   - 地址：插件端所在机器的 IP；
   - 端口：插件端 `server.port`（默认 2123）；
   - 账号/密码：即 conf 中 `jpom.authorize.agent-name` / `agent-pwd`；若密码未配置，可在插件端 `data/agent_authorize.json` 查看自动生成的账号密码（该文件仅本机可读，注意保密）。
2. 在「节点管理」中把机器分配到工作空间，生成节点；
3. 回到节点列表确认节点在线（openStatus 正常），并逐一检查监控、项目、脚本、文件、日志等功能。

:::tip 验证插件端本身是否可用
在插件端机器上执行 `curl http://127.0.0.1:2123/`，应返回一行文本：`Jpom-Agent,Can't access directly,Please configure it to JPOM server`；其它接口需要鉴权头，正常由 Server 调用，无需手工访问。
:::

## 8. 卸载

```bash
bin/AgentGo.sh stop
# 备份数据后再删除目录（data/ 含项目/脚本/授权信息）
tar czf ~/jpom-agent-backup-$(date +%Y%m%d).tgz -C /opt/jpom/agent conf data
sudo rm -rf /opt/jpom/agent
# 如注册过 systemd：sudo systemctl disable --now jpom-agent && sudo rm /etc/systemd/system/jpom-agent.service
```

:::danger 删除 data/ 前务必确认
data/INSTALL.json 记录安装 ID，data/agent_authorize.json 记录鉴权凭据；直接删除会导致 Server 侧节点失联或需要重新绑定。
:::
