# Jpom 2.11.13 安全修复公告

> 发布日期：**2026-11-07** ｜ 修复版本：**2.11.13** ｜ 受影响版本：**2.11.12 及更早版本**（其中 CVE-2026-120201 为 **2.10.0–2.11.12**）
> 适用对象：所有使用 Jpom 服务端（Server）与插件端（Agent）的用户
> 本公告只描述受影响范围、修复情况与防护建议，**不包含漏洞利用细节**。

## 1. 结论

- **受影响的版本**：`2.11.12` 及更早的所有版本（Server 与 Agent）；其中 **CVE-2026-120201 影响 `2.10.0`–`2.11.12`**。
- **已修复版本**：`2.11.13`，于 **2026-11-07** 发布（稳定版）。
- **风险等级**：严重。本次共修复 3 个已分配 CVE 编号的漏洞（最高 **CVSS 9.8**，未授权即可接管管理员权限）和 1 个依赖组件远程代码执行风险（QVD-2026-45876），另包含多项安全加固。
- **建议动作**：**立即升级到 `2.11.13`**。无法立即升级的，请按第 7 节做临时缓解，并按第 8 节排查处置。

::: danger 重要
Jpom 自 2026-02-05 起暂停的是**常规功能迭代**；本次 **`2.11.13` 安全修复版已发布**，旧版本不会再获得本次修复。**安全维护仍在继续**，后续安全问题的处理请关注本安全公告。
:::

## 2. 已修复的安全问题

| 编号 | 风险等级 | 问题说明 | 受影响版本 | 修复版本 |
| --- | --- | --- | --- | --- |
| CVE-2026-120201 | 严重（CVSS 9.8） | 用户身份校验缺陷：未授权的请求可能被错误识别为管理员，导致**管理员权限被接管**（对应早期报告的 `JPOM-USER-TOKEN` 校验问题） | 2.10.0–2.11.12 | 2.11.13 |
| CVE-2026-111605 | 高危（CVSS 8.1） | SSH 文件管理接口未校验资产所属工作空间，可能造成**跨工作区的 SSH 文件读取与写入**（同类 FTP 文件接口已一并修复） | ≤ 2.11.12 | 2.11.13 |
| CVE-2026-91993 | 中危（CVSS 4.3） | 构建仓库相关接口未校验工作空间归属，可能造成**跨工作区的仓库信息访问** | ≤ 2.11.12 | 2.11.13 |
| QVD-2026-45876 | 高危 | 内置依赖 `fastjson2` 的 AutoType 绕过问题可导致**远程代码执行**（影响 `fastjson2` ≤ 2.0.62）；2.11.13 已将 `fastjson2` 升级到 2.0.66 | ≤ 2.11.12 | 2.11.13 |

::: tip 关于版本区间
上表中除 CVE-2026-120201（影响 2.10.0–2.11.12）外，“≤ 2.11.12”指以受影响依赖/代码构建的全部历史版本。若您使用的版本更旧，同样建议升级到 2.11.13。若跨大版本升级（如从 2.10.x 升级），升级前请先阅读对应的迁移指南：[2.10.x 升级到 2.11.x](/pages/upgrade/2.10.x-to-2.11.x/)。
:::

## 3. 其他安全加固

除上述 CVE 外，2.11.13 还包含以下安全收紧（均已在 CHANGELOG 中公开）：

- **JWT 签名密钥随机化**：未配置 `jpom.user.token-jwt-key` 时不再回退到源码中的固定值，首次启动自动生成随机密钥并持久化到 `<data>/.jwt-key`（权限 600）；空白配置同样视为未配置。
- **可信代理校验**：新增 `jpom.web.trusted-proxies`，修复伪造 `X-Forwarded-For` / `X-Real-IP` 绕过 IP 白名单与登录 IP 失败锁定的问题。
- **插件端授权密码保护**：Agent 自动生成的授权密码不再明文写入日志，`data/agent_authorize.json` 权限收紧为 600。
- **`/tools` 网络工具收紧**：`/tools/net-ping`、`/tools/net-telnet`、`/tools/ip-list` 改为仅系统管理员可用，并限制端口/超时、增加操作日志；普通用户仍可使用 Cron 工具。
- **登录验证码加固**：验证码校验前移并改为一次性、5 分钟有效；账号不存在与密码错误统一返回，降低账号枚举风险。
- **系统初始化校验**：初始化接口补充用户名、密码参数校验，避免异常请求创建管理员账号。
- **数据库查询加固**：主键条件以及分页过滤、排序字段统一使用占位符绑定和字段名白名单校验，降低查询条件注入风险。
- **依赖升级**：Tomcat 9.0.123、JGit、BouncyCastle、commons-lang3、fastjson2 等依赖升级，修复其已知安全漏洞。
- **信息暴露收敛**：节点监控异常通知不再包含完整异常堆栈。

## 4. 影响范围

- 部署了 **2.11.12 及更早版本** Jpom 服务端（Server）的实例。
- 部署了 **2.11.12 及更早版本** Jpom 插件端（Agent）的实例（建议与服务端同步升级）。
- 以下场景风险更高，请优先处理：
  - 服务端端口 `2122` / 插件端端口 `2123` 可直接从公网访问；
  - 多用户、多工作空间、多人协作的环境；
  - 开启了 OpenAPI 或对外提供了 API 调用入口；
  - 服务端所在主机上还存在其他重要数据或凭据。

::: warning
本次包含“未授权即可利用”的严重问题，**即使系统只在内网使用也建议升级**；依赖组件风险也不依赖有效登录凭据，可能被未授权请求触发。
:::

## 5. 升级方式

> 升级前请先备份数据目录（默认 `data/`）与配置文件（`conf/`），并阅读第 6 节注意事项。

### 5.1 在线升级（推荐）

1. 使用系统管理员登录服务端。
2. 进入 **系统管理 → 在线升级**，点击检查更新，确认目标版本为 `2.11.13`。
3. 点击升级服务端，等待重启完成（通常 1 分钟内）。
4. 进入 **节点管理**，对插件端执行批量升级（或逐个节点更新），确保 Agent 与服务端版本一致。
5. 刷新页面，在 **系统管理 → 关于/版本信息** 中确认版本为 `2.11.13`。

详细说明：[升级版本](/pages/FQA/upgrade/)

::: tip 检测不到新版本
2.11.12 及更早版本的在线升级功能通常可以检测到 2.11.13。若因网络、证书或旧版本自身问题检测不到，请使用 5.2 手动下载升级。
:::

### 5.2 手动下载升级

1. 打开[下载中心](/pages/all-downloads/)，选择 `2.11.13`，下载与服务端/插件端对应的安装包，并校验 `.sha1`。
2. 停止服务，备份数据与配置。
3. 替换安装包/`jar`，启动服务。
4. 确认版本为 `2.11.13`，检查节点在线与业务功能。

服务端/插件端升级命令与手动替换步骤见[升级版本](/pages/FQA/upgrade/)。

::: danger 下载域名
旧下载域名 `d.jpom.download` **已停用**，请使用新域名 **`d2.jpom.download`**；请从[下载中心](/pages/all-downloads/)进入，谨防仿冒站点。
:::

### 5.3 Docker 镜像

```bash
# 服务端（请替换容器名、端口与数据目录挂载为你自己的配置）
docker pull jpomdocker/jpom:2.11.13
# 插件端
docker pull jpomdocker/jpom-agent:2.11.13
```

- `latest` 标签自 2026-11-07 起指向 `2.11.13`，但生产环境建议使用固定版本标签。
- 容器升级时请确保**数据目录已挂载到宿主机**，再重新创建容器，避免数据丢失；未挂载时先备份容器内数据。
- 容器安装与挂载说明：[容器安装](/pages/820286/)

## 6. 升级注意事项

1. **升级后可能需要重新登录**：未配置 `jpom.user.token-jwt-key` 的实例，升级后会自动生成 `<data>/.jwt-key`，旧的登录 token 失效，需要重新登录；**集群部署必须为所有节点显式配置相同的 key**。建议显式配置至少 32 位随机 `jpom.user.token-jwt-key`，并在升级后确认登录正常。
2. **反向代理环境**：如果反向代理不在本机，请把代理地址配置到 `jpom.web.trusted-proxies`。否则 IP 白名单和登录 IP 失败锁定看到的是代理 IP——这是本次安全收紧，不是升级故障。
3. **`/tools` 权限变化**：`/tools/net-ping`、`/tools/net-telnet`、`/tools/ip-list` 现在仅系统管理员可见/可用，普通用户菜单会隐藏；普通用户的 Cron 工具不受影响。
4. **验证码变化**：验证码改为一次性、5 分钟有效；失败或过期后需要重新获取，账号不存在与密码错误统一提示。
5. **服务端与插件端版本尽量保持一致**，避免出现数据字段/接口不匹配问题。
6. **先在测试环境验证**，尤其是使用了反向代理、集群、OpenAPI 或自定义集成脚本的环境。

## 7. 无法立即升级时的临时缓解

::: danger 缓解不等于修复
以下措施只能降低被利用的概率，**不能替代升级到 2.11.13**。请尽快安排升级窗口。
:::

- **收敛网络暴露面**：不要把 `2122` / `2123` 直接暴露到公网；使用防火墙/安全组白名单、VPN 或带认证的反向代理访问。
- **限制 API 入口**：关闭或限制 OpenAPI，并轮换已发放的 OpenAPI token；限制可访问来源 IP。
- **在反向代理/WAF 上拦截异常请求**：对异常的 `JPOM-USER-TOKEN` 请求、可疑的批量 API 请求增加拦截或告警规则（只能作为兜底，无法阻止全部利用方式）。
- **收紧账号与权限**：为所有账号开启 MFA；删除不再使用的账号，按最小权限收回管理员权限；限制工作空间成员。
- **轮换敏感凭据**：修改管理员密码、插件端授权密码、`jpom.user.token-jwt-key`（修改后旧 token 全部失效）、SSH/FTP/Docker 资产凭据、数据库账号密码、Git 仓库凭据。
- **加强审计**：开启并定期检查用户操作日志、SSH 命令日志、构建与脚本执行记录，关注异常登录时间与来源。

## 8. 是否可能已被利用：自查与处置建议

Jpom 无法远程判断您的实例是否已被攻击，请按下表自查：

| 自查项 | 检查位置 | 需要关注的情况 |
| --- | --- | --- |
| 管理员账号 | 系统管理 → 用户管理 | 出现未知管理员账号、账号权限被提升 |
| 登录记录 | 系统管理 → 用户操作日志 | 异常来源 IP、非工作时间登录、失败登录激增 |
| 工作空间与资产 | 工作空间、SSH/FTP/Docker 资产 | 出现未知工作空间、未知节点、未知 SSH/FTP/Docker 资产 |
| 构建与仓库 | 在线构建、仓库管理 | 出现未知构建任务、未知仓库地址或 webhook |
| 脚本与定时任务 | 在线脚本、节点脚本、Cron | 出现未知脚本、未知定时任务 |
| 主机与网络 | 主机侧进程、出站连接、安全告警 | 未知进程、可疑外联、异常流量 |
| 插件端 | `data/agent_authorize.json`、Agent 日志 | 授权文件异常、日志中有明文密码（旧版本问题） |

若发现可疑迹象，建议：

1. **先隔离**：断开公网访问或停止服务，保留日志与磁盘快照用于取证，不要直接删除现场。
2. **升级到 2.11.13**，并在干净环境完成排查后恢复业务。
3. **轮换所有可能暴露的凭据**：管理员与用户密码、`jpom.user.token-jwt-key`、插件端授权密码、OpenAPI token、SSH/FTP 资产凭据、数据库账号、Git 仓库凭据；其他复用同一凭据的系统也一并轮换。
4. **复核并清理**未知账号、权限组、定时任务、构建、脚本、webhook、资产与节点。
5. 评估数据与内网的影响，必要时重装系统并从可信备份恢复；按贵司安全流程上报。

## 12. 常见问题（FAQ）

### 旧版本还能在线升级到 2.11.13 吗？

可以。登录后进入 **系统管理 → 在线升级** 检查更新即可；若旧版本因网络或自身问题检测不到，请从下载中心手动下载 `2.11.13` 升级。

### 只升级服务端、不升级插件端可以吗？

建议**服务端与插件端都升级到 2.11.13**。本次修复以服务端为主，但插件端也有安全加固（授权密码不再写日志等），且版本不一致可能引入兼容问题。

### Docker 的 `latest` 现在是安全版本吗？

是。自 2026-11-07 起 `jpomdocker/jpom:latest` 与 `jpomdocker/jpom-agent:latest` 指向 `2.11.13`。已经运行旧容器的用户需要重新拉取镜像并重新创建容器，仅重启旧容器不会升级。

### 升级后为什么需要重新登录？

未显式配置 `jpom.user.token-jwt-key` 的实例，升级后会自动生成随机 JWT 密钥，旧 token 失效。这是安全加固，不是故障；集群环境请为所有节点配置相同的 key。

### 升级后反向代理环境的 IP 白名单/登录锁定看起来不正常？

请确认已在 `jpom.web.trusted-proxies` 中配置反向代理地址，否则系统只能看到代理 IP。详见第 6 节。

### 项目是不是已经停止维护了？

Jpom 自 2026-02-05 起暂停的是**常规功能迭代**（见[项目暂停维护公告](/pages/project-suspended/)）；本次 **2.11.13 安全修复版已发布**，**安全维护仍在继续**，后续安全问题请关注本安全公告；也欢迎社区继续提交 PR。

### 继续使用旧版本可以吗？

不建议。`2.11.12` 及更早版本存在本公告所述的严重安全问题，且不会再获得修复；如确实无法立即升级，请至少完成第 7 节的临时缓解并尽快升级。
