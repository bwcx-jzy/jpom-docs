管理 Python 项目脚本示例

# 适用场景

Jpom 的 Dsl 运行方式特别适合托管 Python 应用，因为它不限制你用什么方式启动：

  • Flask / FastAPI / Django（gunicorn、uvicorn）
  • 定时脚本、爬虫常驻进程
  • 需要 venv 隔离的多个 Python 版本

用 Python 3

Python 2 已于 2020 年 EOL，python、python2、SimpleHTTPServer 这些写法不建议再用于新项目。 本文所有示例都用 python3 / venv。

# Linux 脚本（gunicorn 托管 Flask / FastAPI）

项目目录结构：

项目目录/
├── app.py
├── requirements.txt
├── venv/            # 依赖环境（首次部署时创建）
└── project.sh       # DSL 调用的脚本

project.sh：

#!/bin/bash
TAG="pyapp-${PROJECT_ID}"
LIB="${PROJECT_PATH}"
VENV="${LIB}/venv"
LOG="${LIB}/run.log"
APP="app:app"                 # gunicorn 的 模块:变量
BIND="0.0.0.0:8000"

status_pid() {
  pgrep -f -- "$TAG" | head -1
}

start() {
  if [ ! -x "$VENV/bin/python" ]; then
    echo "venv not found: python3 -m venv $VENV"
    exit 1
  fi
  cd "$LIB" || exit 1
  echo "$TAG" > "$LIB/tag"
  nohup "$VENV/bin/gunicorn" "$APP" \
    --bind "$BIND" \
    --pid "$LIB/gunicorn.pid" \
    --access-logfile "$LIB/access.log" \
    --error-logfile "$LIB/error.log" \
    --daemon false > "$LOG" 2>&1 &
  sleep 2
  tail -n 10 "$LOG"
}

stop() {
  pid=$(status_pid)
  [ -z "$pid" ] && { echo "not running"; return; }
  echo "stopping $pid"
  kill "$pid"
  for i in $(seq 1 10); do
    [ -z "$(status_pid)" ] && break
    sleep 1
  done
  pid=$(status_pid)
  [ -n "$pid" ] && kill -9 "$pid"
}

status() {
  pid=$(status_pid)
  if [ -n "$pid" ]; then
    echo "running:$pid"
  else
    echo "stopped"
  fi
}

case "$1" in
  start)   start  ;;
  stop)    stop   ;;
  restart) stop; start ;;
  status)  status ;;
  *) echo "usage: $0 {start|stop|restart|status}"; exit 1 ;;
esac

匹配不到进程时，用 pid 文件更稳

上面用 pgrep -f 依赖启动命令里带唯一标识。如果进程名不好匹配（例如直接用 uvicorn）， 改用 gunicorn 的 pid 文件判断更可靠：

status() {
  pid=$(cat "$LIB/gunicorn.pid" 2>/dev/null)
  if [ -n "$pid" ] && kill -0 "$pid" 2>/dev/null; then
    echo "running:$pid"
  else
    echo "stopped"
  fi
}

# DSL 配置

description: Python 应用（gunicorn）
run:
  start:
    scriptId: project.sh
    scriptArgs: start
  status:
    scriptId: project.sh
    scriptArgs: status
  stop:
    scriptId: project.sh
    scriptArgs: stop
  reload:
    scriptId: project.sh
    scriptArgs: restart      # 没有热重载能力时，用重启代替
  fileChangeReload: true     # 发布新代码后自动重载
  execPath: ./

fileChangeReload 的用途

构建发布把新代码同步到项目目录后，Jpom 检测到文件变动会自动执行 reload。 对 Python 这类「改代码要重启」的应用，把 reload 指向重启脚本最实用。

# 依赖怎么装

依赖安装不要放进 start 流程（每次启动都装会很慢），两种做法：

做法 怎么做
手动装一次 在【SSH管理】的终端里 cd 项目目录 && python3 -m venv venv && venv/bin/pip install -r requirements.txt
交给构建 在【在线构建】的构建命令里装依赖，产物目录填整个项目目录

# 常见问题

Q：报 python3: command not found

A：插件端不加载登录 shell 的 PATH。要么装到系统路径，要么在脚本里写绝对路径（/usr/bin/python3）。

Q：启动成功但状态一直「未运行」

A：确认 status 最后一行是 running:<PID>；用 pgrep 匹配时注意别把自己匹配进去。

Q：改了代码要手动重启才生效

A：把 reload 流程配上，并打开 fileChangeReload: true。

Q：python2 的老项目怎么办

A：仍可托管，把脚本里的 python3 换成 python2、启动方式换成对应的老写法即可；但建议尽快迁移到 Python 3。
