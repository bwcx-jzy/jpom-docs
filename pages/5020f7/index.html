容器构建的 DSL 配置

# 先分清两个 DSL

Jpom 里有两处用 YAML DSL，不是同一个东西：

项目 DSL 容器构建 DSL（本文）
在哪配 【节点&项目】->【项目列表】-> 运行方式选 Dsl 【在线构建】->【构建列表】->【新增】-> 构建方式选 容器构建 -> 第 3 步「构建流程」
作用 描述项目的启动/停止/状态流程 描述构建容器里装什么环境、跑什么命令
顶层字段 run、file、config runsOn、fromTag、steps、binds、copy、env、hostConfig

构建方式创建后不能改

本地构建和容器构建是两种构建方式，选定后不支持修改。要用容器构建就新建一个构建任务。

# 完整示例

# 基础镜像：内置可选 ubuntu-latest、ubuntu-git、ubuntu-1ms-latest、ubuntu-1ms-git
# 也可以填你自己的基础镜像
runsOn: ubuntu-1ms-latest

# 用哪个 docker 执行构建：填 docker 标签，留空取第一个可用的
fromTag: build-node

steps:
  # 装环境：uses 后面是插件名，version 必填
  - uses: java
    version: 8
  - uses: maven
    version: 3.8.7
  - uses: node
    version: 16.3.0
  # python3 / go 按需打开
  # - uses: python3
  #   version: 3.6.6
  # - uses: go
  #   version: 1.17.6

  # 缓存 maven 本地仓库：path 必填，type: global 表示多个构建共享
  - uses: cache
    path: /root/.m2
    type: global

  # 缓存 node_modules：mode: copy 用拷贝方式（避免软链引起 npm 警告）
  - uses: cache
    path: ${JPOM_WORKING_DIR}/web-vue/node_modules
    mode: copy

  # 真正执行的命令：至少要有一步 run
  - run: npm config set registry https://registry.npmmirror.com
  - run: cd ${JPOM_WORKING_DIR}/web-vue && npm i && npm run build
  - run: cd ${JPOM_WORKING_DIR} && mvn package -Dmaven.test.skip=true

# 宿主机目录挂载到容器（只读用 :ro）
# binds:
#   - /root/.m2/settings.xml:/root/.m2/settings.xml:ro

# 宿主机文件复制进容器（第三个参数 true 表示只复制目录内容）
# copy:
#   - /root/settings.xml:/root/.m2/:false

env:
  NODE_OPTIONS: --max-old-space-size=900

# 容器资源限制（Docker HostConfig 字段）
# hostConfig:
#   CpuShares: 1
#   CpuCount: 2
#   memoryReservation: 1g

# 字段与校验规则

# runsOn（必填）

容器的基础镜像。内置可直接用的：ubuntu-latest、ubuntu-git、ubuntu-1ms-latest、ubuntu-1ms-git， 也可以是任意可拉取的镜像名。必须符合镜像名格式，否则保存时直接报错。

# fromTag（可选）

指定用哪个 Docker 节点来执行构建。不填则取当前工作空间里第一个可用的 Docker。 字符白名单：字母数字开头，允许 . _ : / -（长度 ≤ 192），不要带引号、空格、注释符。

# steps（必填）

一个列表，每项要么是 - uses: <插件>（装环境/缓存），要么是 - run: <命令>（执行）。

三条硬校验（保存时就会拦）

  1. 至少有一个 run，否则报「steps 中没有 run」
  2. uses 必须是字符串；env 必须是键值对（map）
  3. maven / gradle 必须同时声明 java，否则报依赖错误

支持的 uses 插件：

插件 必填参数 说明
java version 仅支持 8 / 11 / 17 / 18 / 21 / 25，填其它值直接报错
maven version 版本必须在清华镜像源里存在（保存时会联网校验），且需要同时声明 java
gradle version 版本必须能在 gradle 官方分发地址下载，且需要 java
node version 版本必须在 npmmirror 存在（保存时联网校验）
go version 版本必须在 studygolang 存在
python3 version 必须以 3. 开头，版本需在华为云镜像存在
cache path 缓存目录，支持 type: global（全局共享）、mode: copy（拷贝而非软链）

自定义插件

不在上表里的 uses 会去找插件里的 uses/<名字>/install.sh。没有就报「不支持的插件」。

# run

在容器里执行的命令。构建容器里已经 checkout 好仓库代码，用 ${JPOM_WORKING_DIR} 可以拿到它的绝对路径。内置变量：

变量 含义
${JPOM_WORKING_DIR} 仓库代码所在目录
${JPOM_BUILD_ID} 本次构建记录 ID

# binds / copy / env / hostConfig

字段 用途 示例
binds 宿主机目录挂载进容器 /root/.m2:/root/.m2:ro
copy 宿主机文件复制进容器 /root/settings.xml:/root/.m2/:false
env 容器环境变量 NODE_OPTIONS: --max-old-space-size=900
hostConfig 容器资源限制（Docker HostConfig） CpuCount: 2、memoryReservation: 1g

# 常见问题

Q：保存时报「请填写正确的 maven 版本」

A：保存时会去清华镜像源（mirrors.tuna.tsinghua.edu.cn/apache/maven/maven-3/）校验版本是否存在。 把版本改成镜像源里真实存在的，例如 3.8.7、3.9.6。

Q：报「maven 插件依赖 java」/「gradle 插件依赖 java」

A：steps 里补一条 - uses: java 且 version 用 8/11/17/18/21/25 之一。

Q：构建很慢，每次都重新拉依赖

A：给依赖目录加缓存，例如 - uses: cache + path: /root/.m2 + type: global。 另外「其他配置」里的【缓存构建】打开后，仓库代码也不用每次重新克隆。

Q：node 版本一直报不存在

A：node 版本走 registry.npmmirror.com 校验，写完整的 16.3.0 这种三段式版本号，不要写 16。

Q：容器构建用不了

A：容器构建需要先在【Docker管理】里添加 Docker 并分配到当前工作空间，且宿主机能访问公网拉镜像。 另外：用容器方式安装的 Jpom 服务端不能用本地构建（容器里没有宿主机环境）。
